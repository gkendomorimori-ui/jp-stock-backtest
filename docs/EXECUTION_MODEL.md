# 約定モデル（実行モデル v1 / v2）

作成：2026-09-29。1〜2章は v1（`src/backtest/engine.py`、コミット `639efe6` 時点）の確認結果。
**3章以降が、2026-09-29 に採用した実行モデル v2（基準モデル）の仕様**。v1 は v2 との差を確認する診断用としてだけ残す。
**戦略の条件（シグナル・購入候補・利確 +10%・損切り −5%・保有期限など）は変えない。** ここで扱うのは、それらの条件を「どの価格で・約定できたとみなすか」という約定モデルだけ。

## 1. 以前のモデル（実行モデル v1、診断用）

| 場面 | 発動の判定 | 約定の基準価格 | コスト |
|---|---|---|---|
| 買い（寄付） | T+1 に四本値がある | 始値 | 基準価格 × (1 + 0.1%)、手数料 0.05% |
| 損切り（寄付） | 始値 ≤ 損切り水準 | 始値 | 基準価格 × (1 − 0.1%)、手数料 0.05% |
| 利確（寄付） | 始値 ≥ 利確水準 | 始値 | 同上 |
| 損切り（日中） | 安値 ≤ 損切り水準 | **損切り水準そのもの** | 同上 |
| 利確（日中） | 高値 ≥ 利確水準 | **利確水準そのもの** | 同上 |
| 保有期限・期間終了（引け） | 終値がある | 終値 | 同上 |

- 利確水準 = 購入価格 × 1.10、損切り水準 = 購入価格 × 0.95（購入価格はスリッページ込みの約定価格。端数あり）
- 「約定できない」とみなすのは、その日の四本値が null（無約定・終日売買停止）の場合だけ

## 2. 確認結果

### 2.1 利確水準が呼値に一致しない場合

- **現状：** 利確水準（例：1,001 × 1.10 = 1,101.1円）を、呼値に合わせずにそのまま約定価格の基準にしている。実際にはこの価格では注文できない
- **発動の判定は問題ない：** 高値は必ず呼値の上にあるので、「高値 ≥ 1,101.1」は「高値 ≥ 1,102」（呼値1円の場合）と同じ意味になる
- **約定価格が問題：** 実際の売りの指値は、利確水準以上で最も近い呼値（1,102円）になる。現在のモデルは、実際より最大1呼値分だけ安く約定したことにしている（利益を少なく見積もる方向）
- **影響：** 通常の株価では小さい（1,000円台で最大0.1%程度）。**株価10円未満では大きい**（例：6.6円 → 7円で約6%）

### 2.2 損切りの発動水準と約定価格

- **現状：** 発動水準（購入価格 × 0.95）と約定の基準価格を区別していない。日中に発動した場合は、発動水準そのもの（端数あり）で約定したことにしている
- **実際の想定：** 逆指値の成行注文なら、発動後に最初に成立した価格で約定する。その価格は、発動水準以下で最も近い呼値か、それより安い。日足だけでは、どこまで下で約定したかは分からない
- **影響：** 現在のモデルは、実際より高く売れたことにしている（損失を小さく見積もる方向）。差は最低でも「発動水準から、その下の呼値まで」。株価10円未満では大きい（例：4.75円 → 4円で約16%）
- 寄付で下回った場合は始値で約定（現状どおり。こちらは適切）

### 2.3 呼値とスリッページの区別

- **現状：** 呼値の処理はない。スリッページ（0.1%）を、すべての約定価格にかけるモデル上のコストとして扱っている
- 寄付・引けの約定（始値・終値）は、もともと呼値の上にある価格なので、呼値の処理は不要。問題は 2.1・2.2 の、水準で約定する場合だけ
- **注意：** スリッページ 0.1% は、呼値の刻みよりずっと小さい場合がある（株価6円なら0.006円。呼値は1円 = 約17%）。現在のコストの設定は、低位株の実際の売買の不利さ（最低1呼値の差）を表していない。**これは設定値（0.1%）の性質であり、今回の確認では設定を変えない**

### 2.4 ストップ高・ストップ安、売買停止

- **現状：** その日に四本値があれば、必ず約定したことにしている。J-Quants の `UL`（ストップ高フラグ）・`LL`（ストップ安フラグ）は、加工の段階で捨てていて使っていない
- `UL` / `LL` の意味（J-Quants 公式仕様）：**その日の高値（安値）が制限値幅の上限（下限）に一度でも達したら 1**。終値で判定したものではない
- **問題になる場面：**
  - ストップ高で寄り付いた日に、寄付で買えたことにしている（実際は買いが殺到し、比例配分で買えないことが多い）
  - ストップ安で寄り付いた日・終日ストップ安に張り付いた日に、寄付や日中の損切りで売れたことにしている（実際は売れないことが多い）
  - 引けがストップ安の日に、引けで売れたことにしている
- 終日の売買停止（四本値が null）は、すでに約定しない扱いになっている（問題なし）。日中の一時的な売買停止は、日足からは分からない

### 3.2 利確・損切り（価格の4つの区別）

| 項目 | 意味 | trades.csv |
|---|---|---|
| 発動水準 | 利確 = 購入価格 × 1.10、損切り = 購入価格 × 0.95（端数あり。価格ではない） | `trigger_level` |
| 注文価格 | 利確の指値 = 発動水準**以上で最も近い呼値**（切り上げ）。損切りは逆指値の成行なので注文価格はない（空欄） | `order_price` |
| 約定の基準価格 | スリッページをかける前の、モデル上の約定価格 | `base_price` |
| スリッページ後の価格 | 基準価格 × (1 − 0.1%)。**モデル上の実効価格で、実際に観測した約定価格ではない** | `exit_price` |

| 場面 | 発動の判定 | 基準価格 |
|---|---|---|
| 利確（日中） | 高値 ≥ 発動水準（高値は呼値の上にあるので、高値 ≥ 注文価格 と同じ） | **注文価格**（発動水準を呼値に切り上げた価格） |
| 損切り（日中） | 安値 ≤ 発動水準 | **発動水準以下で最も近い呼値**（切り下げ）。発動後に最初に成立した価格の近似。それより下で約定した可能性は日足ではわからないため考慮しない（**楽観的な仮定**） |
| 損切り（寄付） | 始値 ≤ 発動水準 | **始値**（切り下げた損切り価格ではない） |
| 利確（寄付） | 始値 ≥ 発動水準 | 始値（v1 と同じ）。注文価格も記録する |
| 保有期限・期間終了（引け） | — | 終値 |

- 同じ日に利確・損切りの両方に届いたら損切り優先（v1 と同じ）。判定は発動水準で行う
- スリッページ（0.1%）・手数料（0.05%）は変えない

### 3.3 ストップ高・ストップ安（日足からの厳しめの仮定）

J-Quants の `UL` / `LL` は「その日の高値（安値）が制限値幅の上限（下限）に**一度でも**達したら 1」（終値で判定したものではない）。次の場合を「約定しない」とみなす。**これは日足からの厳しめの仮定で、実際に約定しなかったことを確認したものではない**（比例配分での一部約定、張り付く前の約定は考慮しない）。

| 場面 | 約定しないとみなす条件 | その後 |
|---|---|---|
| 買い（寄付） | `UL = 1` かつ 始値 = 高値（ストップ高で寄り付いた） | 取消（`cancelled_limit_up`）。翌日に持ち越さない |
| 売り（寄付） | `LL = 1` かつ 始値 = 安値（ストップ安で寄り付いた） | 売り要求を翌営業日に持ち越す。**その日の日中・引けには約定させない** |
| 損切り（日中） | `LL = 1` かつ 高値 = 安値（終日ストップ安に張り付き） | 売り要求を持ち越す |
| 売り（引け） | `LL = 1` かつ 終値 = 安値（ストップ安で引けた） | 売り要求を翌営業日の寄付に持ち越す。期間の最終日なら「要確認」 |

- `UL` / `LL` と当日の四本値は**約定の再現にだけ**使う。前日のシグナル・順位・数量には使わない（テストで確認：フラグを変えてもシグナルは同じ）
- `UL` / `LL` の**欠損を 0 とみなさない**。加工では `"0"` / `"1"` 以外（欠損・空文字・想定外の値）を NaN のまま残す。判定が必要な場面（その注文が約定できるかを決める場面）で欠損していたら、`limit_flag_missing` として記録し、**その場で実行を止める**（制限なしとして約定させない。2026-09-29 修正）。判定が不要な日の欠損は問題にしない
- ストップ安の判定（`LL = 1` かつ 始値 = 安値 など）は、**すでにある売り要求が約定できるか**の判断にだけ使う。この条件だけで売り要求を作ることはない（売り要求は、損切りの条件・保有期限・前日からの持ち越しでだけできる。テストで確認）
- 加工済みデータ（`manifest.json` の `limit_flags`）と品質確認（`limit_flags`）で、取引のある行の欠損件数を確認する

### 3.4 売り要求の持ち越し

- 損切りが発動した時点、保有期限（20営業日目の引け）に達した時点で**売り要求**になる。売り要求は、その後に価格が戻っても取り消さず、**実際に売れるまで**残る。次に取引が成立した日の寄付で、始値を基準に売る
- 売れるまで、**現金と保有枠は解放しない**（その間の新規の買いは、枠が空いていなければ `cancelled_no_slot`）
- 寄付の売りが約定しなかった日は、その日の日中・引けで約定したことにしない。初期の v2 では、翌営業日の寄付に持ち越す。**同じ日の再執行（寄付の後に張り付きが解けて売れる場合など）は再現しない近似**である
- 株式分割・併合があった場合、持ち越し中の売り要求の数量と発動水準も、保有と同じ比率で調整する
- 持ち越した売りは、`trigger_date`（発動日）・`trigger_phase` と `exit_date`・`exit_phase`（実際に売った日・時点）が異なり、`carried_days` と `last_unfilled_cause` に記録される。約定しなかった試行は `sell_unfilled.csv` に1行ずつ記録する
- 期間の最終日にまだ売り要求が残っていたら、`end_of_test_untradable` として「要確認」にする（架空の売却代金は計上しない）
- 売れずに残った銘柄は `open_positions.csv` に、未決済の株数・評価額・評価に使った価格とその日付（最後に取引が成立した日の終値）・含み損益を記録する。`summary.json` の `pnl` に、実現損益（決済した取引）と含み損益を分けて記録する（2026-09-29 追加）

## 5. v1 と v2 の比較（開発用期間のみ）

同じデータ・同じ設定で、開発用期間を v1 と v2 の両方で実行し、違いを記録する。**最終評価用・追加確認用の期間では実行しない。**

```powershell
python scripts/run_backtest.py --period development --execution-model v1
python scripts/run_backtest.py --period development
python scripts/compare_execution_models.py --latest   # 最新の v2 と、同じ期間の最新の v1 を比べる
```

- v1 は診断用、**v2 を今後の基準モデル**とする。成績の良し悪しでどちらを使うかを選ばない
- 記録するもの：取引の違い（同じ取引で価格だけ変わったもの、決済が変わったもの、片方にしかない取引）、呼値に合わせた件数、ストップ高・安で約定しなかった件数、持ち越して売った件数、最初に違いが出た日
- 1つの決済が変わると、現金・空き枠・その後の注文が変わる。**損益の合計の差を、個々の原因に割り振らない**（`compare_execution_models.py` も割り振らない。価格だけが変わった取引の差は参考として別に示す）
- v1 の実装が v2 の追加で変わっていないことは、変更前のエンジンと v1 を乱数で作った20通りのデータで比べ、取引・資産推移・注文・状態がすべて一致することで確認した（2026-09-29）
