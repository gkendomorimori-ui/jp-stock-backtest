# 評価計画（high_price_breakout v0.2.0）

作成：2026-09-29。**戦略の成績を見る前に**条件を固定するための文書。
基準戦略の設定・パラメータ（config/backtest.yaml、config/universe.yaml、strategies/high_price_breakout.yaml）は変更しない。

## 1. 進める順序

1. J-Quants を Light プランに切り替え、実際に取得できる期間を確認する
2. **戦略の成績を見る前に**、開発用・最終評価用の期間を日付で固定し、config/backtest.yaml と本文書に記録する
3. 5年分のデータ取得と品質確認、TOPIX 比較処理の実装
4. **開発用期間だけで**、基準戦略と感度分析 A・B を実行する

最終評価用期間では、感度分析も調整も行わない。

## 2. 閲覧済みの期間

動作確認（[記録](smoke_tests/2026-09-28_high_price_breakout_free_plan.md)）で、次の範囲はすでに見ている。

| 範囲 | 期間 | 見たもの |
|---|---|---|
| **成績を閲覧済み** | **2026-04-03 〜 2026-07-03**（62営業日） | 基準戦略の成績、取引の内訳、決済理由、同じ日に両方の水準に届いた件数、購入に至らなかったシグナルの件数など |
| データを取得済み（成績は見ていない） | 2026-03-05 〜 2026-04-02（20営業日） | ウォームアップ。指標の計算にだけ使い、この期間の売買・成績は発生していない |

- 閲覧したのは基準戦略（v0.2.0、既定のパラメータ）の結果だけ。感度分析 A・B の条件での結果は、どの期間でもまだ見ていない
- ただし、この期間について「損切りが多い」「同じ日に両方の水準に届いた取引が11件ある」といった傾向はすでに知っている。**この期間は、以降の分析で「未閲覧」として扱わない**

## 3. 最終評価用期間との重なり

**手順1の結果（2026-09-29 確認）：Light プランで取得できる範囲は 2021-09-29 〜 2026-09-28（営業日1,221日）。** 詳細は [DATA_SOURCES.md](DATA_SOURCES.md)。

当初の方針（5年分のうち、古い約3年を開発用、新しい約2年を最終評価用）をそのまま当てはめると、次のようになる。

- 新しい約2年（最終評価用）：2024-09-30 頃 〜 2026-09-28
- 閲覧済みの 2026-04-03 〜 2026-07-03 は、**この最終評価用期間の中に含まれる**

**→ 重なる。** このまま進めると、最終評価用期間の一部はすでに成績を見ていることになり、「未閲覧の最終評価」とは呼べない。

## 4. 期間の分け方の案（未決定）

取得範囲 2021-09-29 〜 2026-09-28 に当てはめた日付を示す。どの案でも、データの最初の20営業日（2021-09-29 〜 2021-10-26）はウォームアップで、成績には含まない。採用する案が決まったら、成績を見る前に日付を config/backtest.yaml に記録する。

- 開発用期間の末尾の20営業日は、最終評価の指標計算にだけ使う（当初の方針どおり）

| 区分 | 期間（目安） | 扱い |
|---|---|---|

- 長所：開発用期間が約3年のまま
- 短所：最終評価用期間が、一部閲覧済みになる。未閲覧の部分が2つに分かれ（2024年秋〜2026-04-02、2026-07-06〜最新日）、資金を引き継いで通しで評価すると閲覧済みの部分を避けられない。**「未閲覧の最終評価」とは呼べない**

### 案3：最終評価を将来のデータで行う（フォワードテスト）

- 取得できる5年分はすべて開発用とし、最終評価は、今後新しく取得できるデータ（2026年秋以降）で行う
- 長所：確実に未閲覧
- 短所：約2年分のデータがたまるまで、最終評価ができない

**推奨は案1。** 当初の方針（最終評価用は約2年・未閲覧・調整しない）を、閲覧済みの期間を避けたうえで最もよく守れるため。案1を採る場合の、開発用・最終評価用の境目（2024-04-02 / 2024-04-03 付近）は目安で、実際の日付は取得できる範囲と取引所の営業日から決める。

## 5. 感度分析（開発用期間だけで実行する）

共通のルール：

- 基準戦略の設定・パラメータは変えない。変えるのは、各分析で指定した**1つの条件だけ**
- A と B は別々に行い、**2つの条件を同時に変えない**
- どれも、取引の損益だけを書き換えるのではなく、**資金・株数・その後の売買を含めて最初から再実行する**
- 結果を見て基準戦略の条件を変えるかどうかは、この文書の範囲外（別途判断する）
- 最終評価用期間・閲覧済みの期間・追加の未閲覧区間では実行しない

### 感度分析 A：同じ日に利確・損切りの両方に届いた場合の扱い

| 条件 | 内容 |
|---|---|
| 基準 | 損切りを優先する（保守的な仮定） |
| 比較 | 利確を優先する |

- 「利確を優先」は**楽観的な約定の仮定**であり、実際の日中の値動きの順序を再現したものではない
- 比べる項目：基準の評価指標すべて、同じ日に両方に届いた件数、それによって結果が変わった取引、その後の売買（空き枠・資金が変わるため）への影響

### 感度分析 B：購入の順位

| 条件 | 内容 |
|---|---|
| 基準 | 出来高倍率の降順 |
| 比較1 | T-20〜T-1 の平均売買代金の降順 |
| 比較2 | 無作為な順。**乱数シードは 0〜19 の20通りに事前に固定する** |

- どの条件でも、同じ値のときは銘柄コードの昇順で並べる。その他の条件はすべて基準と同じ
- 無作為な順は、20通りすべての結果から**平均・中央値・ばらつき（標準偏差・最小・最大）**を報告する。**成績の良いシードを選んで採用しない**
- 無作為な順の作り方（シードから順位を決める方法）は、実装時に固定してこの文書に書き足し、実行後に変えない
- 比べる項目：基準の評価指標すべて、購入された銘柄の重なり、空き枠がなく取り消した件数の変化
