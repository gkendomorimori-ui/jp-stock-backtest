# Data Sources

## 方針

データソースをバックテストロジックから分離する。

```
Data Provider        （データソースごとの実装：src/data/providers/）
  ↓
Normalized OHLCV     （共通フォーマット：src/data/schema.py）
  ↓
Backtest Engine
```

- 各データソースは `DataProvider` インターフェース（`src/data/base.py`）を実装する
- Provider は取得したデータを **Normalized OHLCV** に変換して返す
- 戦略・エンジンは Normalized OHLCV のみに依存する
- データソースを変更しても戦略コードを変更する必要がない構造とする

**第一候補：J-Quants API V2**（2026-09-27 決定）。上記の分離方針は維持し、他のソースへ差し替えられる構造を保つ。

## データの保存場所

| 場所 | 内容 | Git |
|---|---|---|
| `data/raw/jquants/` | API レスポンスをそのまま保存（全ページを1ファイルにまとめた gzip 圧縮 JSON。日足・銘柄マスタは日付ごと、カレンダーは期間ごと） | 管理外 |
| `data/processed/jquants/` | 加工済みデータ（Parquet、下記の共通フォーマット） | 管理外 |
| `.env` | `JQUANTS_API_KEY` | 管理外（`.env.example` だけコミットする） |

- 元データ（raw）は加工せずに残し、加工はいつでも raw から作り直せるようにする
- **取得済みの判定**：全ページを取得し、`.part` ファイルに書いてから名前を変える（アトミックに保存する）まで完了した日だけを「取得済み」とする。途中で止まった場合は完成ファイルが残らないので、次回その日から取り直す
- 通信失敗・権限エラー・不正なレスポンスは**エラーとして止める**。空データとして保存しない。営業日なのに0件だった場合もエラーにする
- HTTP 429（レート制限）・5xx・通信エラーは、待ってから再試行する（`Retry-After` があれば従う）。それ以外の 4xx は再試行しない
- カレンダーは期間指定で1回だけ取得する（日付ごとには取らない）
- 加工時に、期間内の営業日で日足または銘柄マスタのファイルが1日でも欠けていたら、エラーで止める
- J-Quants のデータは再配布できないので、リポジトリには含めない

## J-Quants API V2

| 項目 | 内容 |
|---|---|
| ベース URL | `https://api.jquants.com/v2/` |
| 認証 | ダッシュボードで発行した API キーを `x-api-key` ヘッダで送る（V1 のトークン方式は使わない） |
| 日足 | `GET /v2/equities/bars/daily`（`code` または `date` が必須。`from` / `to` で期間指定） |
| 銘柄マスタ | `GET /v2/equities/master`（`date` を指定すると、その日時点の上場銘柄を返す） |
| 取引カレンダー | `GET /v2/markets/calendar`（`HolDiv`：0 非営業日 / 1 営業日 / 2 東証半日立会 / 3 非営業日（祝日取引あり））。東証の営業日は 1 と 2 |
| TOPIX | `GET /v2/indices/bars/daily/topix`（`O` `H` `L` `C`。データがない日はレコード自体が返らない） |
| ページング | レスポンスの `pagination_key` を次のリクエストに渡す |
| レスポンス | `{"data": [...], "pagination_key": ...}` |

### 日足のフィールド

| フィールド | 意味 | 用途 |
|---|---|---|
| `Date`, `Code` | 日付、銘柄コード（5桁。例：`72030`） | キー |
| `O`, `H`, `L`, `C` | 未調整の四本値 | 約定・資金計算・資産評価 |
| `Vo` | 未調整の出来高 | — |
| `Va` | 売買代金（円） | 流動性フィルタ |
| `AdjO`, `AdjH`, `AdjL`, `AdjC`, `AdjVo` | 分割・併合を調整した値 | シグナル計算 |
| `AdjFactor` | 調整係数。権利落ち日に値が入る（1:2 分割なら `0.5`） | 保有株数・価格の調整 |
| `UL`, `LL` | ストップ高・ストップ安のフラグ | 今は使わない |

- 取引が成立しなかった日（無約定・終日売買停止など）は、四本値・出来高・売買代金が **null** になる。バックテストではこの日を「約定不可」として扱う
- 上場廃止銘柄も、データ格納期間内であれば上場していた期間のデータを取得できる

### 銘柄マスタのフィールド

`Date`, `Code`, `CoName`, `CoNameEn`, `S17`, `S17Nm`, `S33`, `S33Nm`, `ScaleCat`, `Mkt`, `MktNm`, `Mrgn`, `MrgnNm`, `ProdCat`

| 0101 / 0102 / 0104 | 東証一部 / 東証二部 / マザーズ（2022-04-03 まで） | ○ |
| 0106 / 0107 | JASDAQ スタンダード / グロース（2022-04-03 まで） | ○ |
| 0105 | TOKYO PRO MARKET | × |
| 0109 | その他 | × |

| コード | 名称 | 対象 |
|---|---|---|
| 011 | 国内株式 | ○（ただし下記の注意） |
| 012 | 優先出資証券 | × |
| 013 | REIT | × |
| 014 | ETF | × |
| 021 | 外国株式 | × |
| 022 | 外国REIT | × |

- 公式仕様によると、`011`（国内株式）には**普通株と優先株の両方**が含まれる。`ProdCat` だけでは普通株を取り出せない
- 方針：普通株だと確定できないものは、**推測で普通株に含めない**（`unclassified_policy: exclude`）

### 普通株の判定ルール（確定 2026-09-27）

**普通株 = `ProdCat = 011` かつ 銘柄コード（5桁）の5桁目が `0`**

- 根拠（公式）：証券コード協議会の規則では、普通株式は固有名コード（4桁）だけで表し、それ以外には5桁目に予備コードを付ける（新株式 `1`、第二新株式 `2`、優先株式 `5` `6`、その他の種類株式 `3` `4` `7` `8`、新株予約権証券 `9`）。J-Quants の5桁コードでは、普通株の5桁目は `0` になる
- 根拠（実データ）：2026-06-01 時点の銘柄マスタ（Free プラン、動作確認）で照合した結果は下表のとおり。5桁目が `0` 以外の `011` は6件で、すべて名称に「（優先株式）」が付いていた
- この条件に当てはまらないものは「分類保留」として、普通株に含めない

|---|---|---|

| 対象市場外 | 710 | TOKYO PRO MARKET（`011`）181件、その他（REIT 63・ETF 411・外国ETF 55） |
| 商品区分で除外 | 7 | 優先出資証券（`012`）2件、外国株式（`021`）5件 |

- 対象市場の中に、ETF・REIT は1件もなかった（ETF・REIT は市場区分「その他」に入っている）

### プランごとの制約

| プラン | 日足の取得期間 | レート制限（リクエスト/分） |
|---|---|---|
| Free | 12週間前〜約2年前（12週間遅れ） | 5 |
| Light | 最大5年 | 60 |
| Standard | 最大10年 | 120 |
| Premium | 最大20年 | 500 |

- TOPIX（`/v2/indices/bars/daily/topix`）は **Free プランでは使えない**。Light：5年、Standard：10年、Premium：20年
- TOPIX 以外の指数（`/v2/indices/bars/daily`）は Standard 以上

- **過去5年の検証には Light プラン以上が必要。** Free プランでも接続確認はできる

#### Light プランで取得できる範囲（確認済み 2026-09-29、`scripts/check_plan_range.py`）

| データ | 最初の日 | 最新の日 | 備考 |
|---|---|---|---|
| TOPIX | 2021-09-29 | 2026-09-28 | 1,221件（営業日ごと） |
| 日足 | 2021-09-29（4,120銘柄） | 2026-09-28（4,449銘柄） | |
| 銘柄マスタ | 2021-09-29（4,120件） | 2026-09-28（4,449件） | |
| 取引カレンダー | 2021-09-29 | 2026-09-28 | 営業日1,221日。TOPIX の日付と完全に一致 |

- 最新の日は確認日の前営業日。**Free プランのような12週間の遅れはない**
- 範囲より前の日付を指定すると HTTP 400（`Your subscription covers the following dates: 2021-09-29 ~`）。範囲をまたぐリクエストは、範囲内の分だけを返すのではなく**丸ごと拒否される**
- 最初の日は「確認日の5年前」で、**毎日1日ずつ後ろにずれる**。古い日から順に取得するので通常は問題ないが、取得を何日にも分けると、最初の数日が範囲外になって取得できなくなる可能性がある
- TOPIX（`/v2/indices/bars/daily/topix`）が取得できることも、この確認で確かめた
- 前場・後場のデータは Premium のみ（このプロジェクトでは使わない）

## 共通フォーマット（加工済みデータ）

`scripts/process_data.py` が `data/processed/jquants/` に作る（実装：`src/data/processing.py`）。

### bars.parquet（1行 = 1銘柄 × 1日）

| 列 | 意味 | 元のフィールド |
|---|---|---|
| `date` | 取引日 | `Date` |
| `symbol` | 5桁の銘柄コード（例：`72030`） | `Code` |
| `open` `high` `low` `close` | **実際の**四本値（未調整）。売買が成立しなかった日は NaN | `O` `H` `L` `C` |
| `volume` | 実際の出来高（株数） | `Vo` |
| `turnover` | 売買代金（円） | `Va` |
| `adj_factor` | 調整係数（下記） | `AdjFactor` |
| `adj_open` 〜 `adj_close`、`adj_volume` | **調整後**の四本値・出来高。このプロジェクトで**再計算**した値（下記） | 実際の値と `adj_factor` から計算 |
| `api_adj_close` | API の `AdjC`。参照用で、計算には使わない | `AdjC` |

### 調整係数の意味・適用日・方向

- `adj_factor` は、株式分割・併合の**権利落ち日（効力発生日）**に値が入り、それ以外の日は 1.0
  - 1:2 の分割 → `0.5`、5:1 の併合 → `5.0`
  - 意味：権利落ち日の実際の株価 ≒ 前日までの株価 × `adj_factor`
- 調整後の値は次のように計算する（`C(t)` = t より**後**〜データの最終日までの `adj_factor` の積）
  - `adj_price(t) = 実際の価格(t) × C(t)`
  - `adj_volume(t) = 実際の出来高(t) ÷ C(t)`
- **方向**：過去の値を、データの**最終日**の株数基準に合わせる。権利落ち日 D の係数は D より**前**の日にだけ掛かり、D 自身には掛からない。最終日は調整後 = 実際の値
- API の `Adj*` 列を使わない理由：API の調整後の値は「取得した時点」の基準で計算されるため、日付ごとに取得時期が違うと基準が混ざる。実際の値と係数から計算し直せば、基準は必ず1つになる
- シグナル（終値と過去20日の高値の比、出来高と過去20日平均の比）は比率だけを使うので、基準をどの日に合わせても結果は同じ。後から分割が起きてもシグナルは変わらない

### 使い分け

| 用途 | 使う列 |
|---|---|
| シグナル・出来高倍率 | `adj_high` `adj_close` `adj_volume`（すべて調整後にそろえる） |
| 流動性フィルタ | `turnover` |
| 約定・株数・資金計算・保有資産の評価 | `open` `high` `low` `close`（実際の値）と実際の株数 |
| 保有中の分割・併合 | `adj_factor`（権利落ち日の寄付前に、保有株数 ×1/f、1株あたりの取得価格・利確・損切り水準 ×f） |

- 分割の前後で実際の価格が変わらなければ（例：1,000円×100株 → 500円×200株）、保有評価額は変わらない（テスト済み）
- 分割・併合だけでは、シグナルは発生しない（テスト済み）
- 注意：その銘柄の行が権利落ち日に存在しないと、係数が取れない。J-Quants は売買不成立の日も四本値 null の行を返す仕様なので、通常は問題にならない

### topix.parquet

- `date, open, high, low, close`：TOPIX（**価格指数**。配当込みではない）。`/v2/indices/bars/daily/topix` から期間指定で1回取得（Light プラン以上）
- 生データは `data/raw/jquants/topix/<from>_<to>.json.gz`。加工時に対象期間で切り出す
- ベンチマークは、評価期間の初日の終値を戦略の初期資金にそろえて換算する（`benchmark_equity`）。対象期間の営業日に1日でも欠けがあれば、数値は `null` にして理由を記録する

### master.parquet・calendar.parquet

- `master.parquet`：`date, symbol, name, market_code, market_name, product_category`（日ごとの銘柄マスタ）
- `calendar.parquet`：`date, hol_div, is_trading_day`（東証の営業日 = `hol_div` が 1 または 2）
- `manifest.json`：期間、行数、分割・併合の件数、四本値の不整合件数など

### 観点の説明

- **取得可能期間**：2 年・5 年・それ以上の検証に足りるか
- **OHLCV**：始値・高値・安値・終値・出来高がすべて揃うか
- **調整後株価**：分割・併合の調整有無、調整方法
- **上場廃止銘柄**：Survivorship bias 回避に必要
- **API 制限**：取得速度・1 日あたりの上限
- **利用条件**：商用利用可否、再配布可否（リポジトリにデータを含めない前提）
- **データ品質**：欠損・誤データの頻度、修正履歴

## 接続確認

`scripts/check_jquants_connection.py` で、少量のリクエストで以下を確認する（手順は README）。

| 確認項目 | 状態 |
|---|---|
| 取引カレンダー・日足・銘柄マスタが API キーで取得できる | **確認済み**（2026-09-27、Free プラン、基準日 2026-06-01） |
| `ProdCat` と市場区分の実データでの件数、分類保留の件数 | **確認済み**（上記の照合結果。旧市場区分の時点は未照合） |
| 既知の上場廃止銘柄の、上場期間中の銘柄情報が取得できる | **確認済み**：ネットワンシステムズ（`75180`）の 2025-03-14 時点のマスタ（プライム、`011`）が取得できた |
| 既知の上場廃止銘柄の、上場期間中の株価が取得できる | **確認済み**：ネットワンシステムズの日足が 2025-02-28〜2025-03-17 の12営業日分、欠損なしで取得できた。最終日 2025-03-17 は実際の最終売買日と一致（上場廃止日は 2025-03-18。株式併合による上場廃止）。2026-06-01 時点の銘柄マスタには存在しない |
| TOPIX が取得できる | **Free プランでは利用不可**（HTTP 403）。公式仕様では Light プラン以上で利用可能（Light：5年、Standard：10年、Premium：20年）。Light プランで確認する |

実データで分かったこと：

- 日足のフィールドは仕様書の項目に加えて `ExRT`、`MktCap` もある（今は使わない）
- 取引カレンダーの 2026-04-22〜06-01 の区分は `1`（営業日）25日、`0`（非営業日）12日、`3`（非営業日・祝日取引あり）4日。東証の営業日は `1` と `2` だけを使う
- Free プランのレート制限（5回/分）は、13秒間隔でも超えることがあった。スクリプトは HTTP 429 を受けたら待ってから再試行するように修正した

- 現在の銘柄一覧に存在しないことだけで「取得不可」とは判断しない。契約の取得可能期間内に上場廃止となった既知の銘柄を使って確かめる
- Free プランでの確認は**動作確認**であり、5年分の正式な評価とは区別する
